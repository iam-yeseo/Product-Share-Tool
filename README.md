# 상품 등록 요청 툴

기존 상품 요청 표와 등록 완료 체크를 유지하면서, 고도몰 등록 자동화에 필요한 카테고리·썸네일·상세페이지 HTML을 함께 준비하는 웹 도구입니다. HTML/CSS/바닐라 JavaScript와 Supabase를 사용합니다.

## 페이지

| 주소 | 용도 |
|---|---|
| `/` | 검색 조건과 목록 ID를 유지하며 `/edit/`로 이동 |
| `/edit/` | 기본 편집 / 자동화 편집 전환, 상품 및 목록 저장 |
| `/view/` | 상품 보기·값 복사·등록 완료 체크·자동화 JSON 내보내기 |
| `/settings/` | 소매/도매 카테고리와 이미지 폴더 설정 |

`?list=<목록 UUID>`를 붙이면 해당 목록을 바로 엽니다. 상단 페이지 이동도 같은 목록을 유지합니다. 페이지 구분은 작업 UI의 차이이며 로그인 권한 구분은 아닙니다.

## 기본 편집

1. **+ 새 리스트 등록**으로 목록을 만듭니다.
2. 작성일과 작성자를 입력합니다. 둘 다 저장에 필요합니다.
3. **+ 행 추가** 또는 **엑셀 불러오기**로 상품을 채웁니다.
4. **편집 완료 · 저장** 또는 `Ctrl/⌘ + S`로 공유합니다.

기존 표, 행 선택·복사·삭제·순서 변경, 열 너비 조절, 공용 열 숨김, 가격 연결 기능을 유지합니다. 행 복사는 등록 완료 상태를 복제하지 않습니다. 엑셀은 기존 양식 및 확장 양식의 열 매핑을 확인한 뒤 교체하거나 이어 붙일 수 있습니다. 파일은 브라우저에서만 분석하며 엑셀 내부 이미지는 가져오지 않습니다. 썸네일은 이미지 열에서 별도로 첨부합니다.

편집 중 다른 목록이나 페이지로 이동하면 저장하거나 변경을 버릴 수 있습니다. 저장은 목록 정보와 상품 변경을 하나의 DB 트랜잭션으로 처리하며, 보기 페이지에서 체크한 `done`/`done_at`은 편집 저장으로 덮어쓰지 않습니다.

## 자동화 편집

**자동화 편집 → 상품 선택 → 상품 자동화 정보** 또는 표의 이미지/자동화 정보 버튼으로 엽니다. 기본 편집과 같은 상품을 수정합니다.

- **카테고리:** 이름과 전체 경로로 검색·선택하고, 소매몰/도매몰 코드를 각각 문자열로 저장합니다. `020001`의 앞자리 0도 보존합니다.
- **원산지:** 고도몰 원산지 칸에 그대로 들어가는 문구(예: `Made in China`). 제조사는 브랜드와 동일하게 처리하므로 따로 입력하지 않습니다.
- **썸네일:** JPG·PNG·WEBP·GIF, 최대 6MB. 파일을 실제 이미지로 읽을 수 있는지 확인하고, 상품 저장 시 Supabase Storage에 업로드합니다. 미리보기·교체·제거·공개 주소 복사를 지원합니다.
- **상세 이미지:** `https://calla.hgodo.com/product/<폴더>/<파일명>` 주소를 생성합니다. NAS 접속이나 파일 목록 조회는 하지 않습니다.
- **파일명:** 브랜드와 제품명을 소문자 영문/숫자로 정리합니다. 제품명 내부 대시와 공백은 제거합니다. 예: `TILTA` + `TA-T108-C-B` → `tilta-tat108cb.jpg`. 두 장이면 `-1`, `-2`를 붙입니다.
- **수동 입력:** 기존 파일명에 대시가 있어도 그대로 입력할 수 있습니다. 이미지마다 폴더·파일명·확장자를 바꾸고, 이미지를 추가·삭제·재정렬할 수 있습니다.
- **검사:** 이미지마다 또는 목록 전체를 검사합니다. 브라우저 이미지 로딩·디코딩·실제 크기로 정상 여부를 판정합니다. 주소가 바뀌면 기존 검사 결과가 무효화됩니다.
- **복사/내보내기:** HTML, 이미지 주소, 썸네일 주소, 상품 JSON 복사 및 저장된 목록 JSON 다운로드를 지원합니다.

```html
<div align="center">
  <img src="https://calla.hgodo.com/product/tilta/tilta-tat108cb-1.jpg">
  <img src="https://calla.hgodo.com/product/tilta/tilta-tat108cb-2.jpg">
</div>
```

주소 형식에 오류가 있는 이미지가 있으면 HTML을 비워 누락된 HTML을 잘못 복사하지 않도록 합니다. 정상 로딩은 해당 상품의 이미지라는 의미가 아니므로 미리보기도 확인하세요. 네트워크/호스트 제한에 따른 실패는 HTTP 404로 단정하지 않고 **로딩 실패** 또는 **시간 초과**로 표시합니다.

## 설정

첨부한 카테고리 원본을 [data/categories.md](data/categories.md), [data/b2b_categories.md](data/b2b_categories.md)에 보관하고 초기 데이터를 [data/automation-settings.json](data/automation-settings.json)으로 변환했습니다.

| 몰 | 1차 | 2차 | 초기 합계 |
|---|---:|---:|---:|
| 소매몰 | 27 | 117 | 144 |
| 도매몰 | 26 | 109 | 135 |

몰별 목록은 독립적입니다. 같은 `009006`도 소매몰은 Canon, 도매몰은 BOLIN이므로 서로 복사해 추정하지 않습니다. 원본에 없는 3·4차 카테고리는 설정에서 추가할 수 있습니다. 코드는 단계마다 세 자리씩 증가하며 상위 코드가 일치해야 합니다. 기존 코드와 상위 관계는 고정하고 이름·기본 폴더·사용 여부를 수정합니다. 코드가 바뀌면 새 카테고리를 추가하고 기존 항목을 사용 중지합니다.

이미지 폴더 21개를 기본 제공하며 추가·이름 수정이 가능합니다. 카테고리에 기본 폴더를 연결하면 하위 카테고리에도 상속됩니다. 초기 연결은 미지정이며 실제 상품에 맞게 설정합니다. 폴더 이름을 바꾸면 설정의 연결만 바뀌고 이미 저장한 상품 주소는 유지됩니다. **변경 반영** 후 상단 **설정 저장**을 누릅니다. 다른 사람이 먼저 저장했으면 충돌을 알리고 초안을 유지합니다.

## 자동화 프로그램 연동

### 등록 상태

자동화 프로그램(별도 폴더의 `register.py`)이 `product_registrations` 테이블에 몰별 상태를 기록합니다. 편집·보기 페이지의 **자동화 정보** 칸에 `소매 완료 #상품번호`, `도매 실패` 같은 뱃지로 표시되고, 마우스를 올리면 실패 사유·경고·시각이 보입니다. 필요한 채널이 모두 완료되면 프로그램이 `done`도 함께 체크합니다. 상태 조회에 실패해도 목록 표시는 유지됩니다.

| 상태 | 뜻 |
|---|---|
| 대기 | 아직 시도하지 않음 (등록 필요 채널만 표시) |
| 진행중 | 프로그램이 입력 중 |
| 완료 | 고도몰 저장 확인됨 |
| 실패 | 사전 검증 실패 또는 저장 실패. 사유는 툴팁 |


저장된 상품을 `/view/?list=<UUID>`에서 읽는 방식을 권장합니다. `#automation-data`의 JSON에는 상품 ID, 몰별 코드, 썸네일 공개 주소, 순서대로 정렬된 이미지 주소, HTML, 검사 시각 및 확인 항목이 있습니다. 준비 상태와 예제 코드는 [자동화 데이터 계약](docs/automation-contract.md)을 참고하세요.

## 실행·검증

Node.js와 Python 3가 있으면 별도 패키지 설치 없이 실행할 수 있습니다.

```bash
npm run build
npm test
npm run check
npm start
```

`http://127.0.0.1:8942/`에 접속합니다. 이 주소는 `js/supabaseClient.js`에 설정된 실제 DB를 사용합니다. DB를 사용하지 않는 별도 UI 검증은 `node tests/preview-server.cjs` 실행 후 `http://127.0.0.1:8943/`에서 가능합니다. 검증용 데이터는 해당 브라우저 localStorage에만 저장됩니다. 외부 상세 이미지 검사는 실제 주소를 사용합니다.

Supabase JS는 `2.115.0`으로 고정했고 엑셀 파싱은 SheetJS CDN을 사용합니다. CDN 및 Supabase 연결에는 인터넷이 필요합니다.

## DB와 배포

프론트엔드 배포 전에 [마이그레이션](supabase/migrations/20260907013210_product_automation.sql)을 기존 Supabase 프로젝트에 적용합니다. Supabase migration 이력으로 한 번만 적용하며 기존 상품 및 기존 자동화 설정은 보존합니다.

- `product_items.automation`: 상품별 카테고리·이미지·검사 결과 JSON.
- `app_settings`의 `product_automation_v1`: 공용 카테고리와 이미지 폴더 설정.
- `save_product_draft`: 기존 anon/authenticated 권한으로 호출하는 SECURITY INVOKER 저장 함수.
- `product_registrations`: 몰별 등록 상태 ([마이그레이션](supabase/migrations/20260907120000_product_registrations.sql)). 자동화 프로그램이 기록하고 웹툴은 읽기만 합니다.
- `product-thumbnails`: 공개 이미지 버킷. 기존 목록 UUID 아래 새 파일 업로드만 허용하며 덮어쓰기·삭제 권한은 추가하지 않습니다.

썸네일 교체나 제거는 상품의 참조를 변경합니다. 다른 상품/프로그램이 사용할 수 있는 원본 파일은 Storage에 남습니다. 사용하지 않는 원본 정리는 관리자 권한으로 별도 수행합니다. 썸네일 업로드 후 DB 저장이 실패하면 초안을 유지하고 같은 업로드 주소로 재시도합니다.

기존 프로젝트의 로그인 없는 공유 방식을 유지합니다. 프론트엔드에는 publishable key만 사용하며 service role/secret key는 넣지 않습니다. Supabase RLS와 Storage 정책이 데이터 접근을 결정합니다.

정적 호스팅은 루트 `index.html`, `edit/`, `view/`, `settings/`, `js/`, `css/`를 그대로 제공합니다. GitHub Pages의 기존 도메인 설정은 `CNAME`에 유지되어 있습니다. 공통 편집/보기 HTML은 `templates/product-page.html`을 수정한 뒤 `npm run build`로 두 페이지를 함께 생성합니다.

Cloudflare Workers(Workers Builds · Git 연동) 배포 설정은 [wrangler.jsonc](wrangler.jsonc)에 있습니다. Worker 이름은 `product-upload`, 서버 코드 없이 저장소 루트를 정적 자산으로 제공하며, 사이트에 필요 없는 파일(`package.json`, `scripts/`, `tests/`, `docs/`, `supabase/`, `templates/`, `data/` 등)은 [.assetsignore](.assetsignore)로 업로드에서 제외합니다. 이 설정 파일이 없으면 Wrangler가 배포 대상을 찾지 못해 Workers Builds가 `Missing entry-point` 오류로 실패합니다.
